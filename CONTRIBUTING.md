# Contributing to SubdomainX

Thanks for your interest in improving SubdomainX! This document explains how to
propose changes and what we expect from contributions.

Please also read:

- [AI_USAGE_POLICY.md](AI_USAGE_POLICY.md) — how AI tools may (and may not) be used.
- [AGENTS.md](AGENTS.md) — build/test/convention notes for contributors and AI agents.
- [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md) — community expectations.
- [SECURITY.md](SECURITY.md) — how to report vulnerabilities (do **not** open a public issue).

## Getting started

1. Fork the repository and clone your fork.
2. Create a branch: `git checkout -b feature/short-description`.
3. Make sure you can build and test locally:

   ```bash
   make build
   make test
   go vet ./...
   gofmt -l .   # should print nothing
   ```

## Development workflow

- Keep changes focused — one logical change per pull request.
- Match the style and structure of the surrounding code.
- Keep `main.go` limited to flag definitions and orchestration; put logic in
  `internal/` packages.
- New enumerators go in their own file under `internal/enumerator/` and
  self-register via `init()` calling `RegisterEnumerator()`.
- Add or update tests for any behavior change.
- Never commit API keys, tokens, secrets, or scan output.

## Commit messages

Use clear, conventional messages, e.g.:

```
feat(enumerator): add support for <source>
fix(scanner): handle empty httpx response
docs: clarify config precedence
```

## Pull requests

Before opening a PR, make sure:

- [ ] `make build` succeeds.
- [ ] `go vet ./...` passes.
- [ ] `gofmt -l .` reports no files.
- [ ] Tests pass (`make test`) and new behavior is covered.
- [ ] You have read and comply with the [AI Usage Policy](AI_USAGE_POLICY.md).

Explain the "why" of your change in your own words. PRs that appear to be
generated by fully autonomous agents without meaningful human involvement will
be closed per the AI Usage Policy.

## Reporting bugs and requesting features

- Use the issue templates provided.
- For security issues, follow [SECURITY.md](SECURITY.md) instead of opening a
  public issue.

## Scope

SubdomainX is an offensive-security / reconnaissance tool for **authorized
testing only**. We will not accept features whose primary purpose is to enable
abuse (e.g., built-in denial-of-service, mass untargeted scanning, or detection
evasion for unauthorized use).
